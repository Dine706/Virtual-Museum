# Test area in Unreal Engine

A 300 m square of the summit zone (≈ 1,310–1,500 m, centre 7.6245° N, 8.4010° W) where the montane grassland meets the forest edge. Blender made the assets and the layout; Unreal lights it and lets you walk in it.

| Folder | What |
|---|---|
| `../kit/` | 13 models made in Blender (`*.glb`), `kit.json` (names FR/EN, sizes, triangle counts, what still has to be validated). |
| `../testarea/` | `terrain.glb` (ground, 2 m grid, baked colour), `placements.bin` (about 257,000 plant and rock positions), `testarea.json` (georeferencing, viewpoints, sun). |
| `build_test_area.py` | Unreal Editor script that imports all of it and builds the level `/Game/Nimba/Maps/TestArea`. |

Review pictures of the kit and of this same scene rendered in Blender: `docs/screens/kit/`.

## Status: not yet run in Unreal

The kit, the terrain and the placements were built and rendered in Blender in a cloud session. That session has no Unreal Engine, so **`build_test_area.py` has never been executed**. It uses standard editor Python calls, but expect to correct a few on the first run. The quickest way is to let Claude Code do it on the PC, connected to the editor (setup: `docs/UNREAL_MAC_SETUP.md`, the steps are the same on Windows).

## Run it

1. Pull this branch (`claude/test-area`) on the computer that has Unreal.
2. Open your Unreal project (Blank, with *Python Editor Script Plugin* enabled; *Interchange* glTF import is on by default).
3. *Window → Output Log*, switch the input box from `Cmd` to `Python`, and run the script with the full path:

```
py "C:/path/to/Virtual-Museum/worldpack/unreal/build_test_area.py"
```

4. Open `/Game/Nimba/Maps/TestArea` and press Play. You start in the grass, facing the forest edge.

With Claude Code connected to the editor, paste this instead:

> Read `worldpack/unreal/README.md` and run `worldpack/unreal/build_test_area.py` in the open Unreal project. Fix any Python API error and run again until the level `/Game/Nimba/Maps/TestArea` builds. Then check: plants sit on the ground, the forest is on the same side as in `docs/screens/kit/testarea_overview.jpg`, and take screenshots from the three viewpoints in `worldpack/testarea/testarea.json`. Commit the fixes to the script on `claude/test-area`.

## What to check when it has built

* **Axes.** The script traces the terrain at eight known points to find how the importer oriented the files, and logs the mean height error. It should be a few centimetres. Compare the level seen from above with `testarea_overview.jpg`.
* **Scale.** The ground spans 300 m; the tallest trees are about 25–35 m.
* **Performance.** About 150,000 grass tussocks are instanced with a 90 m draw distance (`CULL_CM` in the script). On a slower GPU, lower it or enable Nanite on the tree meshes.
* **Materials.** Leaves are real geometry (no alpha cut-out), marked double-sided in the glTF. If they look black from below, set the leaf materials to *Two Sided Foliage* shading.

## What is real and what is not

| Part | Source |
|---|---|
| Shape of the ground | Copernicus DEM GLO-30 minus Meta/WRI canopy height, upsampled from 30 m to 1 m: the slope is real, small relief is not. |
| Where trees, grass and rock are | Meta/WRI 1 m canopy height (tree positions follow it, tree height = measured canopy height), ESA WorldCover, slope. |
| Plants and rocks | **Draft models generated in Blender** from the growth forms listed in `../ASSETS.md`. None is a validated model of a named species yet; `kit.json` says what to check for each. |
| Ground and bark textures | CC0 scans from Poly Haven (`public/walk/tex/credits.json`); leaf textures are generated by the script. |

No animals are in the kit. The toad, the bat and the otter shrew are sensitive species, and chimpanzees need a commissioned model and careful treatment (CLAUDE.md §10).
