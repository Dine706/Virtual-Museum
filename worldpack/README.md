# Nimba world pack – stage 1 data for the Unreal world

Everything the photoreal Unreal world is built from: real terrain, real tree heights, land cover, terrain masks, approximate streams, and a species and facts database. All of it is generated by scripts from open data, so it can be rebuilt or extended.

| Folder | What |
|---|---|
| `terrain/massif/` | The whole 3D window: 30.24 km square, 2017 × 2017 px at **15 m**. Heightmaps, canopy, land cover, masks, `streams.geojson`. |
| `zones/<id>/` | Four **hero zones** to explore on foot: 2.016 km squares, 2017 × 2017 px at **1 m**. Same layers, plus a stream mask. |
| `zones.json` | Zone definitions (centres, names FR/EN, why each was chosen). |
| `species/` | `species.json` / `species.csv`: species recorded in the window, with FR/EN names, IUCN category, altitude zones, photo candidates and sources. `gbif_datasets.json`: the datasets to cite. |
| `ASSETS.md` | What 3D assets each zone needs, and where they come from. |
| `REPORT.md` | What is known, what is reconstructed, what is missing; licences. |

All rasters are on the **UTM zone 29N** grid (EPSG:32629, metres, north up). Each folder's `meta.json` gives the exact centre, corners (lon/lat), affine transform, statistics, and the **Unreal import settings**.

## Files in each terrain folder

| File | Format | Meaning |
|---|---|---|
| `heightmap_ground.png` | 16-bit grayscale | **Use this for the Unreal landscape.** Ground surface ≈ Copernicus DSM − canopy height (approximate; see below). |
| `heightmap_dsm.png` | 16-bit grayscale | Copernicus DEM GLO-30 surface *including* the tree canopy, on the same height scale. For reference and checks. |
| `canopy_height_m.png` | 8-bit | Tree height in **metres** (1 grey level = 1 m), from Meta/WRI's 1 m global canopy height map. Drives tree size and density in PCG. |
| `landcover_worldcover.png` | 8-bit | ESA WorldCover 2021 class code: 10 tree, 20 shrub, 30 grass, 40 crop, 50 built-up, 60 bare, 80 water, 90 wetland. |
| `mask_forest.png` | 8-bit weight | 0–255 forest weight (smooth step from 3 m to 12 m canopy). |
| `mask_grass.png` | 8-bit weight | Grassland / shrub / cropland where the canopy is low. |
| `mask_rock.png` | 8-bit weight | Steep ground (≈ 32–42° and over), less where forest covers it: exposed rock and scree. |
| `mask_band_*.png` | 8-bit weight | Indicative altitude bands: lowland < 1,000 m, montane 1,000–1,400 m, summit > 1,400 m (soft 100 m transitions). |
| `mask_stream.png` | 8-bit weight | Streams derived from the ground model (**approximate**, not surveyed). |
| `preview.jpg` | JPEG | Hillshade with forest, grass and streams, for a quick look. |
| `meta.json` | JSON | Georeferencing, statistics, Unreal import settings. |

## Importing a zone into Unreal Engine 5

1. **Landscape mode → Manage → New → Import from File**. Pick `heightmap_ground.png`.
2. Resolution should read **2017 × 2017**. Pick a section/component setup Unreal proposes for that size.
3. Set **Scale X / Y / Z** to the values in `meta.json → unreal_import.scale_cm` (zones: X = Y = 100, i.e. 1 m per vertex).
4. After import, set the Landscape actor's **Location Z** to `unreal_import.location_cm.z`. Heights then match **real metres above sea level** (1 Unreal unit = 1 cm).
5. Landscape layers: import the `mask_*.png` files as weight maps for matching paint layers (forest floor, grass, rock, stream bed…).
6. PCG (procedural forest): sample `canopy_height_m.png` (tree height), `mask_forest.png` (density) and `mask_band_*.png` (which species mix) to place trees, shrubs and grass.

The massif imports the same way (scale X = Y = 1500 cm, i.e. 15 m per vertex): use it for flying and as the distant backdrop around the hero zones.

## Honest limits (read before showing it)

- **Terrain resolution:** the source is 30 m (Copernicus GLO-30). Zones are upsampled to 1 m (cubic), so the *shape* of hills and valleys is real, but rocks, banks and small gullies at walking scale will be **generated detail**, not measurement.
- **Ground under the forest:** the Copernicus DEM is a surface model that includes trees. `heightmap_ground` subtracts the measured canopy height (averaged over 30 m). The result is approximate (radar partly penetrates canopies), but self-consistent: trees placed at their measured height on this ground put the canopy back on the measured surface.
- **Canopy height:** model-derived from satellite imagery with airborne-lidar training (Meta/WRI, mostly 2018–2020 imagery). It is excellent for structure (tall forest vs gaps vs grassland), but individual trees are not identified by species.
- **Streams:** derived from the terrain, not mapped. They follow the right valleys, but positions can be off by tens of metres, and small streams may be missing or extra.
- **Species:** records show where people *collected or observed*, not abundance. Threatened species are flagged `sensitive` and must only appear in generalised zones (no precise locations, same rule as the web demo).

## Rebuilding

```bash
python3 -m venv .venv && .venv/bin/pip install rasterio numpy pillow scipy shapely pyproj requests
```

```bash
.venv/bin/python scripts/worldpack/build_terrain_forest.py
```

```bash
.venv/bin/python scripts/worldpack/build_species.py
```

Raw downloads are cached in `.worldpack-cache/` (git-ignored). The terrain script reads straight from the AWS open-data buckets; the species script needs access to `api.gbif.org`, `query.wikidata.org` and `api.inaturalist.org`.
